# ops-демо «wipe + запись метеостанции: MCP vs руками» (2026-09-20)

Чат «Плата/контент» (единственный держатель COM6). Артефакты: сценарий и оба
скрипта — `D:\project\ironharness-board\tmp\ops-demo\` (worktree чата Б,
детач на f6a9b8d); журнал дорожки B — `tmp/ops-demo/mcp-home/journal.jsonl`.

  На шине второй CH340 (COM3, loc 1-5, немой) — не тронут.
- Файловая система платы до демо: `boot.py` (стоковый), `main.py`
  (метеостанция — байт-в-байт совпал с каноном tmp/meteo_main.py),

- Скан шины: `[118]` (BME280), OLED 0x3C отсутствует (известное состояние),
  DS18B20 сейчас НЕ отвечает (`DS ROMS []` — было живым на кросс-сенсоре
  2026-09-14; владельцу: проверить провод DS жёлтый→D4).
- Прошивка для рефлеша: пин репозитория
  `.ironbench/blink/ESP32_GENERIC-20251209-v1.27.0.bin`, 1 759 456 байт,
  sha256 `aa4be80e…62136b9f` — ровно та же сборка, что стояла на плате.
- Подпись успеха задокументирована ДО демо: свежий бут доходит до main.py

  дисплея нет»; `METEO BOOT` не печатается, пока OLED не на шине.

## Дорожка A — голые руки (`tmp/ops-demo/road-a/`)

Сырые команды: esptool CLI + собственный минимальный raw-REPL клиент на
pyserial (~60 строк: танец входа Ctrl-B/Ctrl-C×2/Ctrl-A, hex-чанки по 256 Б,
парсинг `OK out \x04 err \x04 >`). Ни журнала, ни гейтов, ни капов.

| шаг | команда | время |
|---|---|---|
| wipe | `esptool --chip esp32 --port COM6 --baud 921600 erase-flash` | 5.3 с |
| flash | `esptool … write-flash 0x1000 <bin>` (хэш данных верифицирован esptool) | 21.3 с |
| station | main.py через raw-REPL, 15 hex-чанков + побайтовая сверка размера/краёв | 24.6 с |
| verify | RTS-сброс, чтение 15 с бута | подпись line 89 ENODEV — PASS |

**Грабля №1 (нашла себя на живом прогоне, первый запуск завершился FAIL на
шаге verify):** pyserial при open ассертит DTR/RTS; на этой схеме
авто-ресета `dtr=True` блокирует транзисторную пару RTS→EN — плата молчит на
любые импульсы (диагностика: 0 байт в двух 8-секундных окнах). Наш транспорт
гасит DTR/RTS сразу после open (serial_transport.py:92-93) — «голому» агенту
это знание надо нести в голове. Второй прогон с `dtr=False` — все 4 шага PASS.

**Эвиденс-хвост дорожки A:** только то, что скрипт сам записал в logs/*.log.
Ошибись скрипт впарывале — ни артефакта отказа, ни истории не осталось бы.

## Дорожка B — MCP (`tmp/ops-demo/road-b/`)

Выделенный MCP-сервер (subprocess, `IRONHARNESS_HOME=tmp/ops-demo/mcp-home`),
клиент — line-delimited JSON-RPC (паттерн tests/test_mcp_stdio.py). Оба
прохода в одном транскрипте `logs/transcript.log` и одном журнале.

**NEG (без флага):** `esp_erase` — мгновенный отказ (0.0 с):
`PermissionError: IRONHARNESS_ALLOW_REAL_FLASH=1 is required for live
flash/erase` + `esp_denied` в журнале. Аннотации тулза честно несёт с собой:
`destructiveHint=True`. (Тот же отказ независимо зафиксирован сессионным
сервером ранее в этот день — тоже в его журнале.)

**POS (`IRONHARNESS_ALLOW_REAL_FLASH=1`), 2:08 суммарно:**

| шаг | тул | время |
|---|---|---|
| open/reset/чтение подписи | serial_open, serial_reset, serial_read_until | 0.1–2.1 с |
| (порт закрыт — esptool ходит в порт сам) | serial_close | 0.0 с |
| wipe | esp_erase | 4.8 с |
| flash | esp_flash 0x1000 | 19.7 с |
| main.py в песочницу | file_write | 0.0 с |
| main.py на плату | serial_put 3787 Б (raw-REPL, hex-чанки, тасkside-гейты) | 47.3 с |
| сброс + подпись бута | serial_reset + serial_read_until → `Traceback` найден | 2.1 с |
| round-trip | serial_get 3787 Б → побайтовое сравнение с исходником — **PASS** | 41.5 с |
| финал | session_status, serial_reset, serial_close | 0.0–2.1 с |

**Журнал:** 143 события `кто/когда/что/ответ` — каждый шаг (включая отказ и
каждый hex-чанк туда-обратно) воспроизводим по `mcp-home/journal.jsonl`.
Полный round-trip main.py подтвердил запись независимо от put-ответа.

## Сравнение дорог

- **Работа одинаковая** (4 шага), тайминги сопоставимы (A ~56 с активных vs
  B ~115 с; разница — гекс-протокол put/get и два спавна сервера).
- **Безопасность:** B отказала себе в wipe без явного opt-in и записала отказ;
  A стёрла flash по первому же запуску скрипта — никакой gate не существует.
- **Доказуемость:** B — 143 события журнала (кто/когда/что/ответ) + round-trip;
  A — самописные логи, которые легко НЕ написать.
- **Знание железа:** A потребовало знать DTR/RTS-квирк, полярности
  Ctrl-последовательности, hex-протокол raw-REPL, лимиты cooked-режима;
  B — только имена тулов и аргументы. Это и есть продаваемое ядро io-core.

## Уроки (записаны в память проекта той же сессией)

1. «Голая» дорога на этой схеме мертва без `dtr=False` после open — первый
   прогон дорожки A упал именно тут (урок пойдёт в notes будущих real-задач).
2. serial_put/get на этом CH340 — 40–50 с; клиентский таймаут вызова (30 с у
   ZCode MCP) может истечь, пока серверная передача доезжает: проверять
   результат по песочнице/журналу/session_status, а не только по ответу.
3. Первый live-прогон MCP esp_erase/esp_flash: оба тулза отработали штатно
   (erase 4.8 с, flash 19.7 с, esptool-верификация хэша внутри).

## Конечное состояние платы

- main.py = метеостанция (байт-в-байт канон), boot.py = стоковый;
  smoke_test.py легаси стёрт вместе с wipe и не восстанавливался.
- Прошивка v1.27.0 (та же сборка), плата перезапущена, transport закрыт.
- Бэкапы до-демо состояния: `tmp/ops-demo/preflight/` и
  `~/.ironharness/sandbox/backup-2026-09-20/`.
- БЕЗОПАСНОСТЬ: плата не оставалась без main.py ни в один момент после
  дорожки A/B; между прогонами промежуточных состояний «без станции» не было
  дольше секунд (reflash → тут же put).
