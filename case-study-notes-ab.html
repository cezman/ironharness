Case study: 3 lines of expert notes vs the full feedback budget

4/4 solved on the first iteration with 3 lines of notes — vs 2/4 after burning the full 5-iteration budget, at 10× the wall time.

Setup

One model (zai-org/glm-4.7-flash, local LM Studio), one live bench (ESP32 + BME280 over I2C, MicroPython v1.27.0, USB-UART console), one task (uart-menu — a level-3 finite-state machine with submodes, scored by a runner, not by string equality). Two arms, interleaved attempt by attempt so bench drift hits both arms equally: notes — the task carries a 3-line expert note block from the human who wired the bench; bare — the same task without the notes. Each attempt: up to 5 iterations of «write firmware → stage it onto the live board → read the board's serial answer → fix». The notes fact is recorded per attempt in results.jsonl; every attempt's error_kind is clean (none/run — no infrastructure failures in the series).

Result (uart-menu, level 3)

ArmSolvedIterations per attemptWall time per arm
notes (3 lines)4/41, 1, 1, 1 (70–146 s each)~7 min
bare2/45, 5, 5, 1 (two honest FAILs: budget exhausted)~73 min

Every notes-attempt solved on its first iteration. The one bare attempt that solved on iteration 1 is sampling luck, not a signal. Three factual lines («the console is the USB REPL, input()/print(), machine.UART is not wired», «input() returns without the trailing newline», «expected markers match literally») replaced the entire feedback loop.

Honesty notes

  • One model, one bench, one day; n=4 attempts per arm. The effect is large enough to be visible without statistics, but generalization to other models is future campaigns' work.
  • Practice that follows: real-hardware tasks of difficulty 2–4 should carry 3–5 lines of expert bench notes in the solve prompt — the notes fact travels with the result for exactly this kind of A/B.
  • Infrastructure incident, kept on purpose: the first launch of the series died on our own harness bug (the backup probe used multi-line code that MicroPython's cooked REPL auto-indents after colons — the probe never executed). The wall-gate correctly stopped the campaign, the results carried error_kind=infra, nothing looked like a model failure. Fixed and re-verified the same day; the series above is the clean rerun.
